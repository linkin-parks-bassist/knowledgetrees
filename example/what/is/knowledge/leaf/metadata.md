A leaf's front matter is generated by `kt add` and `kt rewrite` from answer bodies and command options. It has automated `status: green|yellow|brown` and `revised_at` (timezone-aware ISO 8601). Optional metadata fields are manual `checked_at`, `expires_at` or `expires_every`, and the deliberate `verifiable: true` assertion of complete proof coverage. `kt add`, `kt rewrite`, and `kt combine` set revision time. `kt prove` evaluates status from current proof results but does not change `checked_at`. Status moves down by itself and up only by hand. `kt prove` lowers it (a passed expiry makes a leaf yellow; a failed proof, malformed metadata, or unresolved falsification makes it brown) and never raises it, except that a `verifiable: true` leaf whose proofs all run and pass is green. Raising a leaf means reviewing the whole answer and calling `kt_renew`, which records `checked_at`, clears any brown, re-runs that leaf's own proofs, and leaves it green (brown if a proof fails). Adding or rewriting a leaf keeps its status: a new leaf starts green and a rewrite carries `status` and `checked_at` forward while `revised_at` advances. A combined leaf is as unverified as its worst source. An expired answer needs a new manual check unless complete proof coverage under `verifiable: true` makes passing proofs sufficient. `--no-stamp` writes nothing.

`kt_renew` (shell: `kt renew ADDRESS HASH`) records `checked_at` after an agent has manually reviewed the complete answer it read; calling it is the agent's statement that the whole leaf is accurate. It clears sticky falsification, then re-runs the leaf's own proofs: green when they pass, brown when one fails. `expires_at` or `expires_every` is optional for changeable facts. `expires_every` is anchored to `checked_at`, which `kt add` and a rewrite that sets `--expires-every` start at that moment; without any check it is yellow. A manual check after a fixed `expires_at` satisfies that one-time deadline. Proof verification times stay on their individual `Proof:` markers. Mark a factual leaf `verifiable: true` when its entire content is covered by eligible proofs, after reviewing that coverage. Passing proofs then clear sticky falsification and make the leaf green. No leaf-level proof verification timestamp is needed. `status: brown` preserves a failure until independent repair or complete passing proofs on a verifiable leaf.

Set expiry with `--expires-at TIMESTAMP` or `--expires-every DURATION` on add or rewrite. Set complete proof coverage with `--verifiable` after reviewing every claim and proof. Rewrite preserves these optional fields when the options are omitted; `--no-expiry` and `--no-verifiable` clear them. Only `kt_renew` (`kt renew`) sets manual `checked_at`. Supply only answer Markdown to add or rewrite; do not write front matter by hand.

Use the Markdown answer for substantive evidence, origins, caveats, unresolved blockers, and next checks. Root identity comes from the leaf path. The SHA-256 revision that shell rewrites require comes from a full read of the file. Keep only the flat lifecycle fields, plus `name` and `description` where a harness requires a skill entry point. Put blockers, next checks, origins, and review conditions in the answer. Timestamps require ISO 8601 with a timezone. Unsupported front-matter fields and malformed timestamps make a leaf brown until repaired.

Agent tools hide this metadata: `kt_read`, `kt_lookup`, and `kt_info` return the answer only, with a notice when the leaf is yellow or brown, computed live from these fields. The shell shows the front matter (`kt open`).
