Behavioral evaluation must use the installed harness alone: give an ordinary task
without telling the agent to consult knowledge or naming the expected answer paths.
Inspect the transcript for retrieval before corresponding probes. A coached prompt
does not test the gates. Run only when the configured model has available capacity;
structural and installer checks are not evidence of behavioral compliance.

Observable gates make retrieval obligations visible at the moment an agent is
about to act, rather than relying solely on its recognition of an internal knowledge
gap. Loading the procedure is not evidence that later environment-specific decisions
will consult stored answers; familiar shell probes can bypass an introspective
"look up what you do not know" trigger.

Failed probes, privilege or installation steps, host changes, environment-specific
paths/tools/devices, out-of-repository writes, and host/project-specific assumptions
are concrete lookup events. Keep this small gate list inline in the loaded bootstrap.
A trigger hidden only in a leaf the agent must first choose to read cannot reliably
start the behavior it is meant to enforce.

Concrete branch descriptions and exemplar routes in each orientation turn path
guessing into continuation from a known starting point. Detail belongs in direct
lookup, capture, maintenance, and ingestion answers. Gate plus checked hit means
proceed without duplication; gate plus miss means capture after safe discovery and
verification, before continuing.

Treat this as an operating design, not a claim that a model's future behavior is
mechanically proved. Evaluate fresh-session transcripts for actual descent before
environment probes and before proposed host changes, without granting extra action
authority merely to test the gate.
