A project needs one knowledge authority so agents never have to guess whether a
document, skill, note, or leaf is current. Parallel documentation systems recreate
synchronization work and invite contradiction. In a tree-governed project, reusable
project knowledge lives in `.knowledge`; other sources are external authorities,
primary implementation evidence, or temporary ingestion material.

One authority does not mean one physical root for the entire repository. Any
directory can have a local `.knowledge/`: the repository root owns shared project
facts, while subsystem roots own narrower facts and refinements. These compose by
scope rather than duplicating competing answers. Consult the nearest applicable
root, retrieve broader shared knowledge as needed, and keep each fact's canonical
owner clear.
