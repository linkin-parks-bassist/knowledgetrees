From this repository directory, run `python3 sync-kt-instructions.py --check` to compare curated source guidance with installed global leaves and skill hardlinks. Run `python3 sync-kt-instructions.py` to refresh them after source guidance changes. The intentionally untracked, Git-excluded script defines its current leaf and skill sets in `LEAVES` and `SKILLS`; do not maintain a separate count here. It renders public example scope as personal global scope like the installer and normalizes successful proof timestamps during comparison, but not the `status:` line. The check compares the `status:` line, so a leaf whose example and installed copies carry different statuses reports drift that is only a status stamp (for example an expiry that passed in one copy). Run `kt prove --root example` (or a bare `kt prove`) and compare the named leaf's front matter before treating it as real drift; `kt prove` prints only a count. A rewrite keeps a leaf's status, so editing an example leaf and installing normally reports zero drift (verified 2026-09-21, twice).

Replaced content is backed up under `~/.local/state/knowledgetrees/instruction-backups/`. Repository and installed leaves have separate inodes; installed rewrites cannot change public source. Personal leaves, orientations, and project spines are untouched. Executables, hooks, and the MCP server (and its harness registrations) still require installer deployment. When both leaves and tools changed, run the sync first (it makes the backup), then `./install --force`: without `--force` the installer refuses to overwrite differing managed content and lists the paths (`--dry-run` previews that list), it makes no backup of its own, and the sync's leaf set does not include every managed leaf (the MCP design and leaf-metadata leaves were left for the installer on 2026-09-21), so the installer is still needed even for leaf-only changes to those. Verified 2026-09-21: after both steps the sync check reported zero drift and the installed `kt-mcp` was byte-identical to the repository's. The installer removes its former managed home `AGENTS.md` block while preserving unrelated instructions. Updates are manual; refresh after repository guidance changes, then recheck drift and relevant proofs. Restart clients or start fresh sessions to refresh loaded instructions.
